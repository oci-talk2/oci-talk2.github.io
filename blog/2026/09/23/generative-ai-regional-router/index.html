OCI Generative AI에서 Smart Model Router로 서울리전에서 타 리전 모델 사용하기

2026년 9월 23일 · 약 8분

서울 리전(ap-seoul-1) 또는 춘천 리전(ap-chuncheon-1)에서 애플리케이션을 운영하면서, 타 리전에서 제공하는 Generative AI 모델을 사용하려면 어떻게 해야 할까요? OCI Generative AI의 Smart Model Router를 사용하면 서울 리전의 API 엔드포인트로 요청을 보내고, 라우팅 프로파일에 지정한 타 리전내에 있는 모델을 실행할 수 있습니다.

이 글에서는 서울 리전에 라우팅 프로파일을 만들고, xai.grok-4.7 모델을 선택하고, 사용할 리전을 시카고 리전(us-chicago-1)으로 지정한뒤 호출하는 과정을 살펴봅니다.

서울에서 요청하고 시카고에서 추론하기​

2026년 9월 23일 릴리스 노트에서 발표한 Smart Model Router는 사용자가 선택한 리전 범위 안에서 온디맨드 추론 요청을 라우팅하는 기능입니다. 라우팅 프로파일에는 하나의 모델과, 같은 realm(예, Commercial Regions (OC1)) 안에서 해당 모델을 제공하는 대상 리전을 지정합니다.

여기서 모델을 호스팅하는 리전과 요청을 받는 리전을 구분해야 합니다. OCI의 CPU-only 리전 목록에서 서울 리전(ap-seoul-1), 춘천 리전(ap-chuncheon-1)을 CPU-only 접근 지원 리전으로 명시합니다. 서울 리전에 GPU 추론 모델이 없어도, 예를 들면, 서울 리전에서 프로파일을 생성하고 다른 GPU 리전의 모델을 호출할 수 있다는 의미입니다.

따라서 서울 리전을 단순히 “Generative AI를 사용할 수 없는 리전”이라고 표현하기보다는, 이 예제의 모델을 직접 호스팅하지 않지만 리전 간 라우팅을 통해 사용할 수 있는 리전으로 이해하면 정확합니다.

애플리케이션
    │ model = 서울에서 생성한 라우팅 프로파일의 OCID
    ▼
서울 Generative AI API 엔드포인트 (ap-seoul-1)
    │ 프로파일의 대상 리전: us-chicago-1
    ▼
시카고의 xai.grok-4.7 → 추론 결과 반환
구성 요소이 글에서 사용할 값
요청을 받는 API 리전서울, ap-seoul-1
라우팅 프로파일을 생성할 리전서울, ap-seoul-1
프로파일 이름seoul-to-chicago-grok-4dot7
모델xai.grok-4.7
Target OCI regions시카고, us-chicago-1 리전 선택
추론 방식On-demand

애플리케이션이 서울에서 시카고 엔드포인트를 직접 호출하는 구성과는 요청 주소가 다릅니다. 이 글의 호출 주소에는 ap-seoul-1이 들어가며, 추론 위치는 프로파일에서 관리합니다.

1. 사전 준비​

서울과 시카고 리전을 사용할 수 있는 테넌시와, 실습에 사용할 컴파트먼트를 준비합니다. Models by Region에서 선택할 모델의 시카고 온디맨드 지원 여부도 확인합니다. 문서상 xai.grok-4.7는 시카고에서 온디맨드로 제공됩니다. 실제 콘솔에서 테넌시에 표시되는 모델과 대상 리전을 기준으로 진행하세요.

프로파일을 생성하는 사용자에게는 프로파일 관리 권한이 필요합니다. 호출 시에는 추론 작업에 대한 권한과 함께 GENERATIVE_AI_ROUTING_PROFILE_READ 권한도 필요합니다. 아래는 프로파일 관리자 그룹에 부여할 수 있는 정책 예시이며, 그룹과 컴파트먼트 이름은 환경에 맞게 바꿉니다.

Allow group GenAIProfileAdmins to manage generative-ai-routing-profile in compartment GenAI-Demo

이 정책은 프로파일 관리용입니다. 추론 및 API 키 관련 권한은 별도로 구성해야 합니다. 자세한 권한 범위는 API-Level Permissions for Routing Profiles를 참고하세요.

OpenAI API 호환모드로 OCI Generative AI에 연결하기 위해서는 OCI Generative AI API key 생성이 필요합니다. OCI IAM API Key와는 다릅니다. OCI Generative AI API key는 리전 자원이므로 사용할 리전에서 만들어야 합니다. CPU-only 리전에서도 API 키 기능이 제공되므로, 서울 리전의 Generative AI에서 사용할 키를 준비하고, 키에 필요한 접근 권한을 부여합니다. 키 생성 및 권한 설정은 API Keys를 참고하세요.

  1. 콘솔로 서울 리전에 접속하여 키를 생성합니다.

    • https://cloud.oracle.com/ai-service/generative-ai/apiKeys?region=ap-seoul-1

  2. IAM Policy 구문을 생성합니다.

    • 모든 키에 권한을 주는 경우

      allow any-user to use generative-ai-family in compartment <compartment-name> where ALL {request.principal.type='generativeaiapikey'}

    • 특정 키에 권한을 주는 경우

      allow any-user to use generative-ai-family in compartment <compartment-name> where ALL {request.principal.type='generativeaiapikey', request.principal.id='<api-key-ocid>'}

2. 서울 리전에 라우팅 프로파일 생성​

Oracle의 CPU-only 리전에서 모델 접근 절차에 따라, 프로파일은 Generative AI에 접근할 서울 리전에서 생성합니다.

  1. OCI 콘솔의 리전 선택기에서 South Korea Central (Seoul), ap-seoul-1을 선택합니다.

  2. Analytics & AI → Generative AI → Routing profiles로 이동합니다.

  3. Create routing profile을 선택합니다.

  4. 이름에 seoul-to-chicago-grok-4dot7를 입력하고 사용할 컴파트먼트를 선택합니다.

  5. Configuration → Model select에서 xai.grok-4.7를 선택합니다.

  6. Target OCI regions에서 US Midwest (Chicago), us-chicago-1을 선택합니다.

  7. Create를 선택합니다.

  8. 상세 화면에서 상태가 Active인지 확인하고, 모델과 대상 리전을 검토한 뒤 전체 OCID를 복사합니다.

대상 리전에는 선택한 모델이 제공되는 리전만 지정할 수 있습니다. 세부 항목은 Creating a Routing Profile에 설명되어 있습니다.

3. Playground에서 먼저 확인​

서울 리전을 유지한 상태에서 Playground → Chat을 엽니다. 프로파일을 만든 컴파트먼트를 선택한 뒤 Model 메뉴에서 seoul-to-chicago-grok-4dot7 프로파일을 선택합니다.

질문을 입력하고 Submit을 누릅니다.

응답과 함께 Routed model, Serving region을 확인합니다. 이 구성에서 확인할 모델은 xai.grok-4.7, 추론 리전은 us-chicago-1입니다. 서울 리전에서 모델을 사용하더라도 실제 추론은 프로파일에 지정한 시카고 리전에서 수행됩니다.

이 확인 방법은 CPU-only 리전 안내의 Playground 절차를 따릅니다.

4. Python으로 서울 엔드포인트 호출​

공식 라우팅 튜토리얼의 Python 호출 방식을 서울 → 시카고 구성에 맞게 적용합니다.

python3.12 -m venv .venv
source .venv/bin/activate
pip install --upgrade openai

호출할 대상 리전과 라우팅 프로파일 값을 지정합니다.

export OCI_REGION=ap-seoul-1
export OCI_ROUTING_PROFILE_OCID='<서울 리전에서 생성한 라우팅 프로파일의 전체 OCID>'

다음 코드를 routing-chat-completion.py로 저장합니다. 키는 실행 중 화면에 표시되지 않는 입력으로 받으며, 환경 변수로 OCI_GENAI_API_KEY가 있는 경우 그 값을 사용합니다.

"""Chat with an OCI Generative AI routing profile."""

from __future__ import annotations

import os
from getpass import getpass

from openai import OpenAI


def main() -> None:
    region = os.environ.get("OCI_REGION", "us-chicago-1")
    profile_ocid = os.environ["OCI_ROUTING_PROFILE_OCID"]
    api_key = os.environ.get("OCI_GENAI_API_KEY") or getpass(
        "OCI Generative AI API key: "
    )
    client = OpenAI(
        base_url=f"https://inference.generativeai.{region}.oci.oraclecloud.com/openai/v1",
        api_key=api_key,
    )

    messages: list[dict[str, str]] = []
    print("Chat Completions with a routing profile. Type 'exit' to stop.\n")

    while True:
        try:
            prompt = input("You: ").strip()
        except (EOFError, KeyboardInterrupt):
            print("\nGoodbye!")
            break

        if prompt.lower() in {"exit", "quit"}:
            print("Goodbye!")
            break
        if not prompt:
            continue

        messages.append({"role": "user", "content": prompt})
        answer_parts: list[str] = []

        try:
            with client.chat.completions.create(
                model=profile_ocid,
                messages=messages,
                stream=True,
            ) as stream:
                selected_region = stream.response.headers.get(
                    "x-genai-selected-region"
                )
                print(f"Served from OCI region: {selected_region or 'not reported'}")
                print("Assistant: ", end="", flush=True)

                for chunk in stream:
                    if not chunk.choices:
                        continue
                    content = chunk.choices[0].delta.content
                    if content:
                        answer_parts.append(content)
                        print(content, end="", flush=True)
        except Exception as error:
            messages.pop()
            print(f"\nRequest failed: {error}\n")
            continue

        answer = "".join(answer_parts)
        if answer:
            messages.append({"role": "assistant", "content": answer})
        else:
            messages.pop()
        print("\n")


if __name__ == "__main__":
    main()

코드를 실행합니다.

python routing-chat-completion.py

x-genai-selected-region 헤더로 실제 처리 리전을 확인합니다. 헤더가 없으면 not reported가 출력되며, 엔드포인트 주소만으로 추론 위치를 단정할 수 없습니다.

$ python routing-chat-completion.py

5. Private Subnet에 있는 Compute VM에서 확인​

  1. Compute VM을 Private Subnet에 생성합니다.
  2. routing-chat-completion.py 코드 실행할 준비를 합니다.
  3. Private Subnet의 라우팅 테이블에서 Service Gateway만 남기고, NAT Gateway를 제거합니다.
  4. routing-chat-completion.py를 실행하여, 호출이 되는 지 확인합니다.
노트

| CPU-only 접근의 기능 범위도 확인해야 합니다. 문서상 서울과 같은 CPU-only 리전에서는 라우팅 프로파일을 통한 온디맨드 추론을 지원하지만, Embedding API, 전용 AI 클러스터, 모델 가져오기 기능은 제공하지 않습니다. 채팅 호출이 된다는 이유로 다른 Generative AI 기능까지 동일하게 지원된다고 가정하지 마세요. CPU-only 리전별 기능 표에서 필요한 기능을 확인할 수 있습니다.
