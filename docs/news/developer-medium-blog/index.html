Oracle Developers Medium 블로그

Oracle Developers Medium 블로그 업데이트를 자동으로 한국어로 정리요약합니다. 원문은 각 항목의 링크에서 확인하세요. 최신 항목이 맨 위에 표시됩니다.

2026-09-23 업데이트​

  • Karpenter를 활용한 OKE 워크로드 인식형 자동 확장 — Karpenter Provider OCI(KPO)는 OKE에서 워크로드 수요에 따라 노드를 프로비저닝하고 확장합니다. NodePool과 OCINodeClass를 통해 스케줄링 및 OCI 인프라 동작을 정의하며, spot과 on-demand 인스턴스의 가중치를 조정해 비용을 최적화하면서 대체 용량을 확보할 수 있습니다. 또한 static NodePool과 OCI의 shape, 이미지, 네트워킹, 용량 유형을 지원합니다.

2026-09-21 업데이트​

  • Oracle SQLcl MCP Server와 Oracle AI Database를 활용한 Antigravity 워크플로 구축 — Antigravity와 Oracle AI Database를 연결하는 MCP 기반 워크플로 패턴을 소개합니다. MCP는 AI의 데이터베이스 접근을 암묵적인 시스템 권한이 아니라 명시적인 도구 계약으로 정의하며, Oracle SQLcl의 MCP 모드를 통해 데이터베이스 작업을 도구로 제공합니다. 전체 흐름은 Antigravity MCP와 Oracle AI Database 워크플로 노트북에 구현되어 있습니다.
  • 멀티모델 데이터베이스의 가치 — 통합 멀티모델 데이터베이스는 관계형, JSON, 벡터, 텍스트, 그래프, 공간 데이터를 함께 조회하고 갱신할 수 있도록 지원합니다. 이를 통해 hybrid search와 트랜잭션 일관성을 유지하면서 시스템 간 데이터 이동을 줄일 수 있습니다. 구체적인 벡터·JSON·이벤트 스트리밍 예제는 이러한 구성을 구현하는 방법을 보여줍니다.

2026-09-10 업데이트​

  • API 키 없는 Jenkins의 OCI 호출 — OCI 외부에서 실행되는 Jenkins가 영구 OCI API 서명 키를 저장하지 않고 OCI를 호출하는 방식을 소개합니다. Jenkins의 단기 OIDC build token을 단기 OCI session token으로 교환하며, OCI Identity Propagation Trust가 token을 검증하고 build를 OCI service user에 매핑합니다. 실제 접근 권한은 OCI IAM policy가 결정하며, 안정적인 Jenkins 서명 키와 build마다 생성되는 임시 키의 역할을 구분해야 합니다.

2026-09-09 업데이트​

  • 운영 환경을 견디는 agent harness 설계 — 환불 처리 agent가 실제 결제 API 호출에 실패하고도 작업을 완료했다고 보고할 수 있는 운영상 위험을 사례로 설명합니다. 제시된 구조에서는 모델이 작업을 제안하고 harness가 권한을 확인하며 실제 환경이 변경을 적용합니다. agent의 자체 보고를 신뢰하기보다 외부 시스템의 결과를 검증하고 승인과 실행 경계를 분리하는 것이 핵심입니다.

2026-09-08 업데이트​

  • Oracle AI Database와 Java MCP Toolkit 기반 A2UI·MCP Apps 개발 — Oracle AI Database와 Java MCP Toolkit을 이용해 Google Gemini Enterprise App, ChatGPT, Claude에서 동작하는 A2UI 및 MCP Apps 아키텍처를 소개합니다. 백엔드 도구에는 Java MCP Toolkit을, agent 간 또는 host-agent 통신에는 A2A를 활용합니다. 프런트엔드는 신뢰할 수 있는 네이티브 A2UI 컴포넌트나 격리된 MCP Apps로 구성해 렌더링, 상호작용, 실행 경계를 명확히 분리합니다.

2026-09-04 업데이트​

  • Oracle Select AI를 활용한 주식 영상 semantic search 여정 — Oracle AI Database 26ai, Oracle Select AI, vector search와 RAG를 결합해 주식 관련 영상 콘텐츠를 의미 기반으로 분석한 사례입니다. Select AI를 이용하면 자연어로 질문하면서 SHOWSQL로 생성된 SQL을 확인하고 실행 전에 검증할 수 있습니다. vector embedding을 활용해 단순 키워드 집계를 넘어 특정 주식의 위험과 기회처럼 의미 중심의 질문을 처리합니다.

2026-09-02 업데이트​

  • Oracle AI Database 기반 통제형 Cursor MCP workflow — Cursor CLI와 Oracle AI Database를 결합해 AI assistant의 데이터베이스 접근을 통제하고 검사하며 반복 실행할 수 있는 MCP workflow를 제시합니다. MCP는 AI가 시스템에 암묵적으로 접근하는 대신 명시적인 도구 계약을 통해 데이터베이스 기능을 호출하도록 합니다. 이를 통해 실행 권한과 호출 과정을 명확히 관리할 수 있습니다.
  • LangChain.js용 langchain-oracledb 통합 패키지 — Oracle AI Database와 LangChain.js를 연결하는 @oracle/langchain-oracledb 1.0 패키지가 npm에 공개됐습니다. TypeScript와 JavaScript 애플리케이션에서 Oracle AI Database 26ai의 vector search 기능을 사용할 수 있습니다. 문서 수집, 검색 증강 생성(RAG), AI workflow 구축에 필요한 핵심 통합 기능을 제공합니다.

2026-08-28 업데이트​

  • Oracle AI Database용 신규 Thin Go 드라이버 — Oracle이 Oracle AI Database용 공식 순수 Go 드라이버 go-oracledb를 공개했습니다. 이 드라이버는 Go의 표준 database/sql 인터페이스를 구현하며 Oracle AI Database 19c 이상과 TCP 또는 TCPS로 연결됩니다. CGO와 Oracle Client 라이브러리가 필요하지 않아 빌드 의존성을 줄이고 컨테이너 재현성과 크로스 플랫폼 배포를 단순화합니다.
  • 적응형 AI agent 구축 신규 단기 과정 — Oracle과 DeepLearning.AI가 AI agent의 지속적·적응형 학습을 다루는 단기 과정 Building Adaptive AI Agents를 공개했습니다. 이 과정은 시간이 지남에 따라 agent를 개선하는 여러 방식과 Oracle AI Database 26ai에서 이를 구현하는 방법을 설명합니다. agent의 기억과 피드백을 활용해 동작을 점진적으로 개선하는 설계가 핵심입니다.
  • Autonomous Database용 python-oracledb Thin·Thick 연결 모드 비교 — python-oracledb의 Thin 모드는 별도의 클라이언트 설치 없이 순수 Python으로 동작하지만, Thick 모드는 실행 환경에 Oracle Instant Client가 필요합니다. wallet을 사용하는 Autonomous Database 연결에서도 모드별 설정 방식이 다릅니다. 특히 Thin 모드에서는 데이터베이스 암호와 wallet 인증서 파일을 해제하는 wallet_password를 구분해야 합니다.

2026-08-24 업데이트​

  • AI agent의 운영 데이터베이스 접근에서 얻은 교훈 — Oracle은 AI agent가 기업 데이터를 안전하게 조회하고 Oracle AI Database를 영구 메모리로 활용하는 방식을 소개합니다. agent가 직접 SQL을 생성하도록 두는 대신, 데이터 접근을 통제된 도구와 명확한 권한 경계로 제한하는 접근법을 다룹니다. 운영 환경에서는 편의성뿐 아니라 권한 관리, 동작 검증, 감사 가능성을 함께 고려해야 합니다.
