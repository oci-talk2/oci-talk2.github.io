    Spring Boot 에이전트 워크로드에서 Oracle JDBC와 Oracle AI Database 서버 측 실행까지 이어지는 단일 분산 추적을 구성합니다. Java observability provider와 서버 측 OTel exporter를 이용해 애플리케이션과 데이터베이스 구간을 연속적으로 관측하는 방법을 제시하며, 데모용 소스 코드와 설정 및 스크립트도 제공합니다.
  • 운영 RAG 평가를 위한 키워드·벡터·SQL·하이브리드 검색 비교
    운영 RAG 평가는 올바른 근거 검색, 근거 기반 답변, 권한 준수, 최신 데이터 처리 및 지원되지 않는 질문에 대한 답변 거부 여부를 측정해야 합니다. 동일한 질문 집합으로 키워드, 벡터, SQL 및 하이브리드 검색을 비교하고 검색 지표, 답변 품질 검사 및 운영 장애 테스트를 함께 적용합니다.
  • Oracle AI Database 기반 자기 개선형 세컨드 브레인 구축
    사용자가 수용한 수정 사항과 유용한 경험을 Oracle AI Database에 보존해 이후 상호작용에서 더 적합한 컨텍스트를 검색하는 세컨드 브레인을 구현합니다. 이는 저장된 정보를 활용하는 애플리케이션 수준의 적응이며, 자동적인 모델 학습이나 지속적인 성능 향상을 의미하지는 않습니다.

2026-07-16 업데이트​

  • 운영 환경 RAG의 키워드·벡터·SQL·하이브리드 검색 평가
    동일한 질문 집합을 이용해 키워드, 벡터, SQL 및 하이브리드 검색 경로를 각각 평가하는 방법을 제시합니다. 정확한 용어는 키워드 검색, 의미적 일치는 벡터 검색, 최신 정형 데이터는 SQL로 검증하고, 생성된 답변의 근거성, 인용, 최신성, 권한 준수 및 답변 보류 능력도 함께 점검해야 합니다.
  • ACL·테넌트 필터·출처·Oracle Deep Data Security를 활용한 안전한 엔터프라이즈 RAG
    안전한 엔터프라이즈 RAG에서는 검색된 정보가 모델에 전달되기 전에 원본 ACL, 테넌트 ID, 레이블, 출처, 마스킹, 감사 및 삭제 상태를 적용해야 합니다. 단순한 비공개 또는 자체 호스팅만으로는 충분하지 않으며, 검색 계층이 원본 데이터와 동일한 접근 규칙을 따라야 합니다.
  • 실시간 RAG를 위한 Live SQL·증분 인덱싱·최신성 테스트
    자주 변경되는 정형 데이터는 매번 다시 임베딩하지 않고 SQL 또는 NL2SQL로 실시간 조회하는 방식을 권장합니다. 문서는 변경된 chunk만 증분 갱신하고 버전과 타임스탬프를 추적하며, 답변이 오래된 정보보다 최신 근거를 우선하는지 테스트해야 합니다.
  • 테이블·PDF·대화록·미디어를 위한 RAG chunking과 parsing
    RAG chunking은 콘텐츠를 의미 형성에 필요한 문맥과 분리할 때 품질이 저하됩니다. 각 chunk에는 제목, 테이블 헤더, 원본 ID, 타임스탬프, 화자 레이블, 미디어 특성 및 보안 메타데이터를 보존해 검색된 근거 자체가 이해 가능하도록 구성해야 합니다.
  • RAG와 다른 에이전트 메모리: 대화 ID·영속 상태·범위 기반 회수
    RAG는 답변을 위한 외부 근거를 검색하지만, 에이전트 메모리는 사용자, 에이전트, 스레드, 선호도, 결정 및 이전 작업의 선택된 상태를 장기 보존합니다. 대화 ID는 세션을 찾는 데 유용하지만 그 자체로 보존 정책이나 권한을 준수하는 메모리 회수 범위를 정의하지는 않습니다.
  • 삭제 문서·오래된 chunk·중복 임베딩을 통한 RAG 인덱스 드리프트 탐지
    원본 레코드, chunk 해시, 삭제 표식, 임베딩 버전 및 검색 결과를 기준 데이터와 대조해 RAG 인덱스 드리프트를 탐지하는 방법을 설명합니다. 삭제된 콘텐츠가 더 이상 검색되지 않고, 갱신된 콘텐츠가 오래된 chunk를 대체하며, 중복 임베딩이 억제되는지 지속적으로 검증해야 합니다.
  • AI 애플리케이션의 벡터 검색 문제 해결
    신뢰할 수 있는 벡터 검색 문제 해결을 위해 일관된 임베딩, 유용한 chunk, 검색 대상 원본 레코드, 검증된 검색 경로 및 소규모 기준 질문 집합을 마련해야 합니다. 품질이 변하면 동일한 쿼리를 각 계층에서 추적하고 top-k 근거를 검사한 뒤, 변경된 계층을 수정해 테스트를 반복합니다.
