2026-08-21 업데이트​

2026-08-18 업데이트​

2026-08-11 업데이트​

  • Codex와 Oracle AI Database를 위한 제어된 MCP 워크플로우 구축 — Codex CLI를 SQLcl MCP와 연결하고, Oracle AI 에이전트 메모리와 LangChain Retrieval을 추가하는 방법을 설명합니다. 저장된 SQLcl 프로파일, 데이터베이스 사용자, 권한 및 정책이 접근 제어 경계 역할을 유지합니다.

2026-08-10 업데이트​

  • 에이전트 메모리는 데이터베이스 문제: Oracle 연구 결과 — arXiv에 발표된 기술 보고서는 데이터베이스‑네이티브 메모리 서브스트레이트가 장기 에이전트에 적합함을 입증합니다. LongMemEval에서 93.8% 성능을 달성했으며, 평평한 대화 기록 대비 입력 토큰을 약 10.7배 절감했습니다. 거버넌스를 설계 단계에서 고려하도록 제안합니다.
  • AI 에이전트를 위한 맞춤형 메모리 추출: 대화를 유용한 사실로 전환 — Oracle AI Agent Memory는 사용자 정의 추출 지시문, 스레드 수준 오버라이드, 도구 결과 메타데이터를 활용해 지원 대화를 내구성 있는 메모리와 메타데이터로 저장합니다. 이를 통해 에이전트는 대화에서 핵심 사실을 추출하고 재사용 가능한 지식으로 전환할 수 있습니다.

2026-08-05 업데이트​

  • Oracle AI Agent Memory 하이브리드 검색: 의미 검색과 정확 일치 결합 — 지속적인 AI 에이전트 메모리에서 의미적 유사도와 정확한 텍스트 매칭을 동시에 활용하는 하이브리드 검색 방법을 안내합니다. 이 가이드는 Oracle AI Agent Memory를 이용해 두 검색 방식을 결합하는 패턴을 단계별로 설명합니다.

2026-07-29 업데이트​

  • Supervisor 에이전트 소개: Oracle Select AI 기반 다중 에이전트 워크플로우 구축 — Oracle AI Database와 Oracle Autonomous AI Database에서 적응형 에이전트 오케스트레이션을 구현하는 실용 가이드를 제공합니다. 고객 지원 시나리오(결제 실패 확인, 청구 계정 업데이트, 확인 메일 전송)를 단계별로 자동화하면서, 실패 여부에 따라 흐름을 유연하게 조정합니다.

2026-07-22 업데이트​

2026-07-20 업데이트​

  • Oracle AI Database 기반 자기 개선형 세컨드 브레인 구축 — 데이터, 임베딩, 에이전트 메모리를 하나의 Oracle AI Database에 저장해 의미 기반 검색이 가능한 ‘세컨드 브레인’을 구축하는 단계별 가이드를 제공합니다. MCP를 통해 모든 AI 채팅에 연결하고, 자체 개선형 에이전트를 활용해 지속적으로 지식을 확장할 수 있습니다.
  • 프로덕션 RAG 평가: 키워드·벡터·SQL·하이브리드 검색 — 프로덕션 환경에서 RAG를 평가할 때는 동일 질문 세트에 대해 키워드, 벡터, SQL, 하이브리드 검색을 비교합니다. 검색 정확성, 답변 근거, 권한 준수, 최신 데이터 반영, 거부 응답 여부 등을 측정하여 최적의 경로를 선정합니다.
  • 엔드투엔드 에이전트 AI 관측성: 에이전트에서 Oracle AI Database까지 추적 — Spring Boot 에이전트, Oracle JDBC, Oracle AI Database 서버 사이드 실행을 하나의 연속 트레이스로 연결하는 방법을 보여줍니다. Java 관측성 제공자와 서버 측 OTel exporter를 사용하며, 데모에 필요한 모든 소스 코드와 설정 파일은 GitHub의 observability 폴더에 공개되어 있습니다.

2026-07-16 업데이트​

  • AI 애플리케이션 벡터 검색 트러블슈팅 — 신뢰할 수 있는 벡터 검색을 위해 일관된 임베딩, 적절한 청크, 유효한 소스 레코드, 검증된 검색 경로, 알려진 쿼리 집합을 기준선으로 설정합니다. 품질이 저하될 경우 동일 쿼리를 각 레이어별로 추적하고, 상위 k개의 증거를 검토해 문제 발생 레이어를 수정한 뒤 재테스트합니다.
  • RAG 인덱스 드리프트 감지 방법 — 인덱스 드리프트는 소스 레코드, 청크 해시, 삭제 마커, 임베딩 버전, 검색 결과를 원본과 비교하여 감지합니다. 삭제된 문서는 검색되지 않아야 하고, 업데이트된 내용은 최신 청크로 교체되며, 중복 임베딩은 억제되고, 신선도 필터가 테스트되어야 합니다.
  • 에이전트 메모리와 RAG 구분: 대화 ID·지속 상태·범위별 회상 — RAG는 외부 증거를 검색하고, 에이전트 메모리는 사용자·에이전트·스레드·선호도·결정 등 지속적인 컨텍스트를 저장합니다. 이를 위해 대화 ID, 테넌트 스코프, 출처, 삭제 규칙 및 권한 기반 회상이 필요하며, 그렇지 않으면 메모리가 프롬프트에 과다 삽입되어 상태가 누출될 수 있습니다.
  • RAG 청킹·파싱: 테이블·PDF·전사·미디어 — 청킹 시에는 헤딩, 테이블 헤더, 소스 ID, 타임스탬프, 화자 라벨, 미디어 특성, 보안 메타데이터 등을 보존해야 합니다. 적절한 파싱과 청킹은 모델이 증거를 이해하기 전에 의미를 유지하도록 도와줍니다.
  • 실시간 RAG: 라이브 SQL·증분 인덱싱·신선도 테스트 — 실시간 RAG에서는 구조화된 데이터를 SQL 또는 NL2SQL로 실시간 조회하고, 의미 검색이 필요한 문서는 기존 인덱스를 활용합니다. 변경된 문서는 영향을 받은 청크만 증분 업데이트하고, 버전·타임스탬프를 추적해 최신 증거가 우선 사용되는지 테스트합니다.
